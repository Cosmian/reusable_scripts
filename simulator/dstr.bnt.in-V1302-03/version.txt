Évolutions
----------

Spécifications 12.1 (partielles) :

- Nouveaux types de clef MKLORA et DKEK (RM #5919)
- Nouvelle option LORA (RM #5920) et les cinq commandes correspondantes
  (RM #5922, #5923, #5924, #5925, #5974 et #5984)
- Nouveau profil HCE (RM #5971)
- L'option HCE_TMS autorise désormais les commandes de calcul de CVX2,
  de vérification d'AC et de calcul d'ARPC (RM #5972)
- La clef de session devient obligatoire pour un calcul d'ARPC en CVN43
  (RM #5973)
- La commande de vérification de CVx consulte et renseigne désormais la liste
  orange dans le cas des clefs IMKtvv (RM #5780)
- La commande de tirage de clef dynamique permet le chiffrement en AES Keywrap
  (si la clef de chiffrement est de classe AES, bien évidemment) (RM #5887)
- Les 21 courbes elliptiques spécifiées dans ANSI X.9-62 sont désormais
  acceptées et utilisables, à la place du sous-ensemble de 15 courbes
  utilisé précéemment. (RM #5862)

Corrections
-----------

- La commande de tirage de clef symétrique n'était pas utilisable dans
  la version V806-11. (RM #5866)
- La commande de vérification de CVX utilisée avec l'algorithme VISA et
  une clef IMKcvc3 ou IMKtvv provoquait l'insertion d'un PAN incorrect
  en liste orange en cas d'échec. Il s'agit là d'une régression affectant
  toutes les versions V806 <= V806-11. (RM #5983)
- La commande de changement de pin ne vérifiait pas correctement l'égalité
  entre l'IdP de clef IMK et le début de l'IdC de la clef KT lors d'un
  changement de propriétaire. (RM #5903)
- Dans le cas où la commande de tirage de clef dynamique était utilisée avec
  une clef de chiffrement KME ou KTK de classe AES, celle-ci était traitée
  comme une clef DES pour le chiffrement (mais le contrôle du niveau de
  sécurité des clefs était effectué correctement). Le tirage de clef
  statique n'était pas sujet à ce problème. (RM #5889)

Interface d'administration
--------------------------

- Il est désormais possible de restreindre les protocoles SSL/TLS acceptés
  par C2P depuis la page de configuration réseau. Le réglage est global
  et affecte aussi bien les connexions à l'interface d'administration en
  https, que les connexion cryptographiques sur le port 3001. ATTENTION !
  il n'y a pas encore de garde-fou, il est donc possible de « s'enfermer
  dehors » si l'accès non chiffré (http) est désactivé et que les seules
  versions de protocole TLS autorisées ne sont pas supportées par le
  navigateur utilisé. (RM #5171)
- Il est désormais possible de charger des certificats d'AC pour l'export des
  clefs. Ceux-ci ne sont jamais utilisés pour les connexions chiffrées.
  (RM #5921)

Corrections
-----------

- Corrections du traitement de l'authentification des utilisateurs de la base
  de clefs:
  + La commande d'authentification externe provoquait une fuite mémoire dans
    la partition système (RM #5418).
  + L'échec d'authentification utilisateur conservait l'authentification
    existente au lieu de revenir en état « non authentifié » (RM #5419).
  + Une clef USER sans mot de passe défini pouvait être utilisée pour
    s'authentifier sans mot de passe. (RM #5420)

- Plusieurs commandes cryptographiques ne se comportaient pas correctement
  (coupure de la connexion + trace d'exception dans le log) dans certains
  cas d'utilisation de clefs AES avec des données à traiter (vecteurs de
  contrôle, KEV, données à reporter, etc) d'une taille multiple de 8 octets
  mais non multiple de 16 octets, qui auraient dû être rejetés. C'est le cas
  des commandes FF45, FF4B, FF9122, FF8129, FF8202 et FF8203. (RM #5393)

- La conversion d'un pin block dont le code confidentiel est de longueur
  impaire, vers le format ISO1, détruisait la valeur du dernier digit dudit
  code confidentiel. (RM #5452)

- Le tirage d'une clef éphémère de plus de 4000 bits dans le cadre du
  protocole SSL/TLS n'aboutissait pas. (RM #5476)

- La commande de vérification de MAC avec clef dérivée GrDF (FF8220)
  n'acceptait la valeur 15 pour le choix de variante (tag DF 82 62). (RM #5581)

Évolutions
----------

- Spécifications 11.6 (partielles) :
  + Support des algorithmes CVC3 UMD et CVC3 MD dans la commande de
    vérification de CVC3 (Mastercard Cloud-Based Payment) (RM #5423)
  + Nouvelle option HCE_CMS (mais toutes les fonctionnalités HCE_CMS ne sont
    pas encore disponibles) (RM #5440)
  + Nouvelle commande de génération de clef à usage limité FF8228 (RM #5447)

- Interface d'administration :
  + Un nouvelle page de statistiques est ajoutée à l'interface ; celle-ci
    présente, pour chaque commande cryptographique, les temps de traitement
    extrêmes ainsi que le temps de traitement moyen, et donne la possibilité
    de réinitialiser les statistiques, commande par commande.
  + L'affichage des compteurs de vérification de code est déplacé de la page
    "outils" vers la page "statistiques".
